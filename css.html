Grandir, rétrécir : la propriété flex

.enfant { flex: 1 1 0; }
/*        │ │ └ flex-basis : taille de départ */
/*        │ └── flex-shrink : peut rétrécir   */
/*        └──── flex-grow : part de l'espace  */

  • Avec flex-basis: 0, l'espace est partagé proportionnellement aux valeurs de flex-grow : 1, 2, 1 donne ¼, ½, ¼.
  • flex: 1 est un raccourci pour 1 1 0%.
  • flex: none : taille fixe, ni grandir ni rétrécir.
  • min-width: 0 sur un enfant permet à un texte long de rétrécir au lieu de déborder.
  • Animer flex-grow donne de jolis effets d'agrandissement au survol.

  • minmax(190px, 1fr) : chaque colonne fait au moins 190px, et partage le reste.
  • auto-fill : le navigateur met autant de colonnes qu'il en tient. Sur mobile une, sur grand écran six.
  • auto-fit : pareil, mais étire les cartes si elles sont peu nombreuses.
Choisir

Flexbox ou Grid ?

FLEXBOX

Une dimension

  • Le contenu décide de la taille.
  • Barre de navigation, groupe de boutons, centrage.
  • Éléments sur une ligne qui passent à la ligne.
GRID

Deux dimensions

  • La structure décide de la taille.
  • Mise en page de page, galeries, tableaux de cartes.
  • Quand les éléments doivent s'aligner en lignes et en colonnes.

On les combine sans arrêt : une grille de cartes, et du flex à l'intérieur de chaque carte pour aligner l'icône et le texte.

Responsive

Mobile d'abord, puis on élargit

/* styles de base = mobile */
.produits { display: grid; gap: 12px; }

/* à partir de 768px */
@media (min-width: 768px) {
  .produits { grid-template-columns: 1fr 1fr; }
}

/* selon la taille du conteneur */
.zone { container-type: inline-size; }
@container (min-width: 500px) {
  .carte { display: flex; }
}
  • Mobile-first : on écrit d'abord pour le petit écran, puis on ajoute avec min-width. Plus simple que l'inverse.
  • Les media queries regardent l'écran.
  • Les container queries regardent le parent : un même composant s'adapte, qu'il soit dans une colonne étroite ou large.
  • N'oublie pas <meta name="viewport" content="width=device-width, initial-scale=1">.
Organisation

Variables CSS et design tokens

:root {
  /* palette brute */
  --rouge-600: #A41B1B;
  --nuit-900:  #0D2A4A;

  /* tokens sémantiques */
  --accent:      var(--rouge-600);
  --fond:        #FFFFFF;
  --texte:       #1B1A17;
  --rayon:       8px;
}
@media (prefers-color-scheme: dark) {
  :root { --fond: var(--nuit-900); --texte: #FFF; }
}
.bouton { background: var(--accent);
          border-radius: var(--rayon); }
  • Une variable se déclare avec --nom et se lit avec var(--nom).
  • Deux niveaux : la palette (les couleurs) et les tokens sémantiques (le rôle : fond, texte, accent).
  • Les composants n'utilisent que les tokens. Changer de thème = redéfinir quelques tokens.
  • Les variables sont vivantes : on peut les changer en JavaScript ou dans un attribut style.
Tailwind

Le principe : une classe = une propriété

/* CSS classique */
.carte {
  display: flex;
  align-items: center;
  gap: 1rem;
  padding: 1.5rem;
  border-radius: 0.75rem;
  background: white;
}
.carte:hover { box-shadow: …; }
<!-- Tailwind -->
<div class="flex items-center gap-4
            p-6 rounded-xl bg-white
            hover:shadow-lg">
  …
</div>
  • Tailwind lit tes fichiers au build et ne génère que les classes qu'il y trouve écrites en entier.
  • Tu ne nommes plus tes classes et tu ne changes plus de fichier : le style est à côté du HTML.
  • Ce n'est que du CSS : connaître Flexbox et Grid reste indispensable.

Le piège classique

Les valeurs dynamiques

// ✗ ne marche pas : classe jamais écrite en entier
<div className={`bg-${couleur}-500`} />

// ✓ classes complètes dans une table
const fonds = {
  rouge: "bg-red-500",
  bleu:  "bg-blue-500",
};
<div className={fonds[couleur]} />

// ✓ valeur libre : variable CSS + style
<div style={{ "--c": couleur }}
     className="bg-(--c)" />   // v4
//   className="bg-[var(--c)]"     // v3
  • Tailwind ne lance pas ton code : il cherche du texte. bg-${x}-500 n'existe nulle part, donc aucune classe n'est générée.
  • Valeurs connues à l'avance (une liste de couleurs) : une table de classes complètes.
  • Valeurs vraiment libres (une couleur venant de la base) : variable CSS dans style, lue par la classe.

À retenir

L'essentiel en 6 phrases

  • box-sizing: border-box partout.
  • Flex pour une ligne, Grid pour une grille.
  • repeat(auto-fill, minmax(…, 1fr)) = grille responsive gratuite.
  • Mobile d'abord, puis min-width.
  • Des tokens sémantiques plutôt que des couleurs en dur.
  • En Tailwind, les classes s'écrivent en entier ; le dynamique passe par une variable CSS.
Exercices

Teste-toi

Comment centrer une div horizontalement et verticalement dans son parent ?

Sur le parent : display:flex; justify-content:center; align-items:center; (ou display:grid; place-items:center;).

Que fait flex: 2 1 0 à côté de deux éléments en flex: 1 1 0 ?

Il prend la moitié de l'espace, les deux autres un quart chacun : l'espace est réparti selon 2, 1 et 1.

Traduis gap: 14px et border-radius: 10px en Tailwind.

gap-3.5 (3,5 × 4px) et rounded-[10px] (aucune classe par défaut ne vaut 10px).

Pourquoi className={`text-${taille}`} ne fonctionne pas ?

Tailwind génère les classes en lisant le texte des fichiers. La classe complète n'y apparaît jamais, donc elle n'est pas générée. Utilise une table de classes complètes.

Une grille doit avoir une colonne sur mobile et trois à partir de 1024px. En Tailwind ?

grid grid-cols-1 lg:grid-cols-3. Sans préfixe pour le mobile, lg: à partir de 1024px.
