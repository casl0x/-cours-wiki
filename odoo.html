Le contexte

Les modules

  • Chaque application (Ventes, Site web, CRM…) est un module. Un module peut en exiger d'autres : installer Site web installe aussi des modules de base.
  • Les modules installés se gèrent dans Applications. Retire le filtre « Applications » pour voir aussi les modules techniques.
  • Mettre à jour un module recharge ses vues et ses données d'origine.

Pourquoi c'est important

  • Une vue standard modifiée directement peut être écrasée à la mise à jour de son module.
  • Une vue héritée que tu as créée, elle, reste en place.
  • Les thèmes de site sont aussi des modules : ils ajoutent leurs propres vues héritées.

Chaque champ a un libellé (« Surface ») et un nom technique (x_surface). Le code utilise toujours le nom technique. Les champs créés à la main commencent par x_.

Champs

Champs liés et champs calculés

CHAMP LIÉ

Copier une info d'ailleurs

Affiche un champ d'un enregistrement relié. Ex. : sur une commande, la ville du client (partner_id.city).

Pratique pour afficher, filtrer ou grouper sans double saisie. Dans Studio : « Champ lié ».

CHAMP CALCULÉ

Une valeur déduite

Sa valeur est calculée à partir d'autres champs. Ex. : prix au m² = prix ÷ surface.

Par défaut non stocké : recalculé à l'affichage, donc impossible à trier ou rechercher. Le stocker le rend recherchable.

En mode développeur, la fiche d'un champ (Technique → Champs) indique s'il est lié, calculé, stocké, obligatoire ou en lecture seule.

L'outil indispensable

Le mode développeur

L'activer

  • Paramètres → tout en bas → Activer le mode développeur.
  • Ou ajouter ?debug=1 dans l'adresse, après /odoo ou /web.
  • Une icône d'insecte apparaît dans la barre du haut.

Ce qu'il débloque

  • Survoler un champ affiche son nom technique et son modèle.
  • Menu insecte → Modifier la vue : ouvre la vue affichée.
  • Paramètres → Technique : vues, modèles, actions, actions automatisées.

Pour retrouver n'importe quelle vue : Paramètres → Technique → Interface utilisateur → Vues, puis cherche par nom ou par clé (ex. website.layout).

Outils

Studio : personnaliser sans code

  • L'icône Studio (en haut à droite, version Enterprise) ouvre l'éditeur sur l'écran en cours.
  • Glisser-déposer de nouveaux champs dans un formulaire ou une liste.
  • Créer une nouvelle application avec ses propres modèles, menus et vues.
  • Ajouter des filtres, des rapports PDF, des règles d'automatisation.
  • Publier un modèle sur le site web (pages liste et détail).

Ce qu'il fait en coulisses

Studio crée des champs x_studio_… et des vues héritées, exactement comme un développeur le ferait. Tu peux les retrouver et les lire dans Technique → Vues.

Les modifications de Studio sont regroupées dans un module « Studio customizations » que l'on peut exporter.

Outils

Explorer les modèles et les champs

  4. Menu insecte → Afficher les champs : toutes les valeurs brutes de l'enregistrement affiché.

QWEB

Pages web et rapports

Pages du site, e-mails, PDF. Du HTML avec des instructions t-….

  • Le code d'une vue se trouve dans l'onglet Architecture de sa fiche.
  • Une vue a une clé (identifiant stable), un modèle, et éventuellement une vue héritée (parente).
Vues

Lire l'architecture d'un formulaire

<form>
  <header>
    <field name="state" widget="statusbar"/>
  </header>
  <sheet>
    <group>
      <group>
        <field name="name"/>
        <field name="partner_id"/>
      </group>
      <group>
        <field name="date_order"/>
        <field name="x_surface"
               invisible="state == 'draft'"/>
      </group>
    </group>
    <notebook>
      <page string="Détails">…</page>
    </notebook>
  </sheet>
</form>
  • <sheet> : la « feuille » blanche du formulaire. <header> : la barre de statut et les boutons.
  • <group> imbriqués : deux colonnes de champs avec leurs libellés.
  • <notebook> et <page> : des onglets.
  • widget change l'affichage d'un champ (barre de statut, étiquettes, image…).
  • invisible, readonly, required acceptent une condition. Depuis Odoo 17, on l'écrit directement (l'ancien attribut attrs a disparu).
La bonne méthode

Hériter plutôt que modifier

<!-- vue qui hérite de website.layout -->
<xpath expr="//header" position="after">
  <div class="alert alert-info">
    Fermé le lundi
  </div>
</xpath>

<xpath expr="//footer//a[@href='/contact']"
       position="attributes">
  <attribute name="class">btn btn-primary</attribute>
</xpath>

Une vue héritée ne recopie pas la vue d'origine : elle dit où et quoi changer.

positionEffet
before / afterAjoute avant / après
insideAjoute à la fin, dedans
replaceRemplace l'élément
attributesChange un attribut

Les mises à jour d'Odoo réécrivent les vues standard. Tes modifications dans une vue héritée, elles, survivent.

La bonne méthode

Écrire une expression XPath

ExpressionCible
//field[@name='partner_id']Le champ partner_id, où qu'il soit
//div[@id='wrap']La div d'identifiant wrap
//div[hasclass('o_footer')]Une div qui a la classe o_footer (parmi d'autres)
//header//navUne nav n'importe où dans le header
//t[@t-foreach='records']La boucle sur records
(//section)[1]La première section
  • Vise un élément stable (un nom de champ, un identifiant) plutôt qu'une position : la structure peut changer à la mise à jour.
  • Raccourci pour un champ : <field name="partner_id" position="after"> sans écrire de XPath.
Erreur classique

« L'élément … est introuvable dans la vue parente »

Une XPath cherche un élément précis. S'il n'existe pas (ou plus) dans la vue parente, Odoo refuse d'afficher la vue.

  • Un thème ou un module a été conçu pour une autre version d'Odoo.
  • Tu as changé de modèle d'en-tête : le nouveau n'a pas l'élément visé (une barre de recherche, par exemple).
  • Une autre vue héritée a déjà supprimé ou remplacé cet élément.

Pour s'en sortir

  1. Lis le nom de la vue fautive dans le message d'erreur.
  2. Retrouve-la dans Technique → Vues.
  3. Corrige l'expression XPath, ou archive la vue si elle n'est plus utile.
  4. Vérifie ta version d'Odoo avant d'installer un thème ou un module tiers.
Site web

Les vues propres au site

Quand tu modifies une page dans l'éditeur du site, Odoo ne touche pas à la vue générique : il crée une copie liée à ce site web (champ Site web rempli) et c'est elle qui s'affiche désormais.

Symptôme : tu modifies la vue dans Technique → Vues, mais rien ne change sur le site. Tu as modifié la générique, alors que le site affiche sa copie.

Comment éviter le piège

  • Dans la liste des vues, regarde s'il existe deux vues de même clé, dont une avec un site web.
  • Pour du code, passe par le site : Site → Éditeur HTML/CSS/JS modifie toujours la version affichée.
  • Pour revenir à l'original, supprime la copie propre au site.

Site web

La structure d'une page web

<t t-name="website.ma_page">
  <t t-call="website.layout">
    <div id="wrap">

      <div class="oe_structure"/>

      <section class="container py-5">
        <h1>Nos biens</h1>
        …
      </section>

      <div class="oe_structure"/>

    </div>
  </t>
</t>
  • t-call="website.layout" insère la page dans le cadre du site : en-tête, menu, pied de page, CSS.
  • #wrap contient le contenu propre à la page.
  • Les zones oe_structure sont des emplacements libres : on peut y déposer des blocs avec l'éditeur.
  • Les classes container, row, col-md-6, py-5 viennent de Bootstrap, le framework CSS utilisé par Odoo.
QWeb

Les instructions de base

<t t-foreach="records" t-as="bien">
  <div class="card">
    <h3 t-field="bien.name"/>

    <p t-if="bien.x_surface">
      <t t-out="bien.x_surface"/> m²
    </p>
    <p t-else="" class="text-muted">
      Surface non communiquée
    </p>

    <a t-att-href="'/biens/%s' % bien.id">
      Voir
    </a>
  </div>
</t>
InstructionRôle
t-foreach + t-asBoucle sur une liste
t-if / t-elif / t-elseCondition
t-fieldAffiche un champ formaté (date, prix…), éditable dans l'éditeur
t-outAffiche une valeur (remplace t-esc)
t-att-…Attribut calculé
t-callInclut un autre template
<t>Conteneur invisible
QWeb

Variables et attributs dynamiques

<!-- créer une variable -->
<t t-set="nb" t-value="len(records)"/>
<p><t t-out="nb"/> biens disponibles</p>

<!-- classe calculée -->
<div t-att-class="'badge bg-success' if bien.x_dispo else 'badge bg-secondary'">

<!-- texte + valeur mélangés -->
<div t-attf-class="card #{'border-primary' if bien.x_vedette else ''}">
<img t-attf-src="/web/image/{{ bien._name }}/{{ bien.id }}/image_1920"/>
  • t-set / t-value : une variable réutilisable dans la suite du template.
  • t-att-nom : la valeur de l'attribut est une expression Python.
  • t-attf-nom : du texte avec des morceaux calculés, entre #{…} ou {{…}}.
  • L'URL /web/image/modèle/id/champ affiche une image stockée dans un champ.
QWeb

Formater les valeurs

<!-- prix avec la devise -->
<span t-field="bien.list_price"
      t-options='{"widget": "monetary",
        "display_currency": website.currency_id}'/>

<!-- date au format de la langue -->
<span t-field="bien.create_date"
      t-options='{"widget": "date"}'/>

<!-- texte riche (champ Html) -->
<div t-field="bien.description"/>
  • t-field connaît le type du champ : il formate les dates, les montants et les relations selon la langue du visiteur.
  • t-options précise le format (widget).
  • t-out échappe le HTML par défaut : du texte contenant <b> s'affiche tel quel, ce qui protège contre l'injection de code.
  • Un champ de type Html, affiché avec t-field, est rendu normalement.
QWeb

Gérer les listes et valeurs vides

<!-- liste vide -->
<t t-if="records">
  <t t-foreach="records" t-as="r">…</t>
</t>
<t t-else="">
  <p>Aucun résultat pour le moment.</p>
</t>
  • t-else doit suivre immédiatement le bloc t-if, sans autre élément entre les deux.
  • En Python, une liste vide, 0, "" et False sont « faux » : t-if les traite comme absents.
  • Attention : une surface de 0 serait donc considérée comme vide.
  • Le nom de la variable de boucle (records, bien…) dépend de la vue : lis le t-foreach existant avant d'écrire.
Champs dynamiques

Le champ Properties

ParentPorte la définition : la liste des propriétés et leur type. Champ PropertiesDefinition
→
EnfantsPortent les valeurs. Champ Properties qui pointe vers le parent
  • Exemples : le projet pour les tâches, l'équipe commerciale pour les pistes CRM.
  • Les utilisateurs créent les propriétés depuis le formulaire, sans module ni Studio.
  • Chaque propriété a un nom technique aléatoire : ne l'écris jamais en dur dans un template.

« Quand j'en modifie une, ça change partout »

Normal : tous les enregistrements d'un même parent partagent la même définition, quelle que soit la vue. Pour des jeux de propriétés différents, il faut des parents différents (par exemple un modèle « catégorie »).

Données

Les domaines : filtrer des enregistrements

# ET implicite entre les conditions
[('state', '=', 'sale'),
 ('amount_total', '>', 1000)]

# OU : opérateur placé avant
['|',
 ('city', '=', 'Namur'),
 ('city', '=', 'Liège')]

# champ d'un enregistrement lié
[('partner_id.country_id.code', '=', 'BE')]

Un domaine est une liste de conditions (champ, opérateur, valeur). On le retrouve partout : filtres, pages de modèle, règles d'accès, automatisations.

= != > <Comparaisons
in / not inDans une liste
ilikeContient (sans casse)
!= FalseLe champ est rempli

L'éditeur de domaine (mode développeur) construit la liste à ta place.

Pages de modèle

Pages, vues et duplication

Studio peut publier un modèle sur le site sous forme de page liste et de page détail. Une page n'est qu'un pointeur : elle désigne une URL, un modèle, un filtre et une vue.

  • Dupliquer une page ne duplique pas sa vue.
  • Modifier le contenu de l'une modifie donc toutes celles qui partagent la vue.

Deux solutions

  • Une vue par page : duplique la vue et fais pointer la page vers la copie. Pour des mises en page vraiment différentes.
  • Une vue commune avec conditions : t-if sur l'adresse (request.httprequest.path). Pour un titre ou une phrase qui change.
Automatiser

Les règles d'automatisation

Une règle dit : quand ceci se produit, sur ces enregistrements, fais cela.

DéclencheurExemple
CréationNouvelle piste CRM
Modification d'un champStatut passé à « Vendu »
Date3 jours avant l'échéance
Réception d'un e-mailMessage sur un alias

Actions possibles

  • Mettre à jour un champ (archiver, changer un statut).
  • Envoyer un e-mail ou un SMS à partir d'un modèle.
  • Créer une activité ou une tâche.
  • Exécuter du code Python (pour les cas avancés).

Teste toujours une règle sur une base de test : une règle mal filtrée peut modifier des milliers d'enregistrements.

Site web

Langues et traductions

  1. Paramètres → Langues : active la langue (néerlandais, anglais…).
  2. Dans les paramètres du site web, ajoute-la aux langues du site.
  3. Sur le site, choisis la langue puis clique sur Traduire : le texte modifiable apparaît surligné.
  4. Les champs des enregistrements (nom de produit, description) se traduisent depuis leur formulaire, via l'icône de langue.
  • Chaque langue a sa propre adresse : /nl/…, /en/….
  • Les textes écrits en dur dans une vue QWeb sont traduisibles aussi, mais une modification du texte d'origine peut faire perdre la traduction.
  • Pense au référencement de chaque langue : titre et description traduits.
Sécurité

Travailler sans risque

BASE DE TEST

Dupliquer avant

Duplique la base (gestionnaire de bases, ou branche de test sur Odoo.sh) et fais tes essais dessus. Les e-mails sortants y sont désactivés.

COPIE

Sauver l'architecture

Avant de modifier une vue, copie son code dans un fichier. Revenir en arrière prend alors quelques secondes.

ARCHIVER

Plutôt que supprimer

Une vue ou une règle archivée cesse d'agir mais reste récupérable. Une suppression est définitive.

Sur une base de production, une modification à la fois, testée en navigation privée (pour voir le site comme un visiteur non connecté).

À retenir

L'essentiel en 6 phrases

  • Modèle = structure, enregistrement = donnée, vue = affichage.
  • Le mode développeur donne les noms techniques et les vues.
  • On hérite d'une vue avec des XPath au lieu de la modifier.
  • L'éditeur du site crée des copies propres au site.

Exercices

Teste-toi

Où trouver le nom technique du champ « Surface » d'un formulaire ?

Activer le mode développeur, puis survoler le libellé du champ dans le formulaire : une infobulle affiche le nom technique et le modèle.

Tu modifies une vue dans Technique → Vues mais le site ne change pas. Pourquoi ?

Le site affiche probablement une copie de la vue qui lui est propre, créée lors d'une modification dans l'éditeur. Il faut modifier cette copie, par exemple via l'éditeur HTML du site.

Quelle position d'XPath pour changer la classe d'un bouton existant ?

position="attributes" avec <attribute name="class">…</attribute>.

Comment afficher « Aucun bien » quand la liste est vide ?

Entourer la boucle d'un <t t-if="records">, suivi immédiatement d'un <t t-else=""> avec le message.

Pourquoi ajouter une propriété sur une tâche l'ajoute à toutes les tâches du projet ?

La définition des propriétés est stockée sur le projet (le parent) et partagée par toutes ses tâches.
